# EVM Vanity Wallets

[English version](README.md)

Два генератора EVM-кошельков (Ethereum и все EVM-совместимые сети) с поиском
адреса по начальным/конечным символам. Оба ориентированы на использование
с реальными средствами: минимум plaintext, стандартные форматы, самопроверки.

## Установка

```bash
uv venv .venv --python 3.12          # или: python3 -m venv .venv
uv pip install --python .venv/bin/python --require-hashes -r requirements.txt
```

Зависимости полностью зафиксированы с хешами:

| Файл | Содержимое |
| ---- | ---------- |
| `requirements.in` | прямые runtime-зависимости: eth-account, mnemonic, coincurve |
| `requirements.txt` | полный lock (включая транзитивные пакеты) с `sha256`-хешами |
| `requirements-dev.in` / `requirements-dev.txt` | pytest для тестов |

`--require-hashes` отклоняет любой файл, хеш которого не совпал с lock, —
подменённый пакет не установится. Обновление lock: правим `.in` и
перегенерируем:

```bash
uv pip compile requirements.in --universal --python-version 3.10 --generate-hashes -o requirements.txt
uv pip compile requirements-dev.in --universal --python-version 3.10 --generate-hashes -o requirements-dev.txt
```

`coincurve` (C-библиотека libsecp256k1) ускоряет генерацию ключей на порядок —
без неё eth-keys работает на чистом Python-бекенде.

### Установка на офлайн-машине (рекомендуется для реальных средств)

`pip install` требует сеть, поэтому зависимости скачиваем заранее и переносим
на флешке (та же ОС/архитектура, Python 3.10+):

```bash
# на онлайн-машине:
mkdir wheels && .venv/bin/pip download -r requirements.txt -d wheels

# на офлайн-машине (флешка в /media/usb):
python3 -m venv .venv
.venv/bin/pip install --no-index --find-links /media/usb/wheels --require-hashes -r requirements.txt
```

Хеши проверяются на обеих машинах — подменить wheel на флешке незаметно не
получится. pytest на офлайн-машине не нужен.

## vanity_key.py — приватный ключ → зашифрованный keystore

Ключ никогда не печатается и не пишется в plaintext: сразу шифруется в
стандартный **V3 keystore** (Web3 Secret Storage, scrypt) — тот же формат,
что у geth/MetaMask. Импорт: файл + пароль.

```bash
.venv/bin/python vanity_key.py --prefix ab --suffix cd --count 2
.venv/bin/python vanity_key.py --prefix dead --show-privkey   # сырой ключ на экран
.venv/bin/python vanity_key.py --walk --workers 14 --prefix aaaa  # быстрый режим
```

`--walk` — режим дешёвых шагов: один случайный 256-битный старт, дальше ключ
инкрементируется на 1, а публичная точка обновляется одним сложением `P += G`
(~в 7 раз быстрее на том же железе). Энтропийно эквивалентен случайным ключам,
найденный ключ проходит полную независимую проверку (`k·G` заново + сверка).
Требует `coincurve`. **Старт всегда случайный из `os.urandom`** — «красивый»
старт (1, дата, простой сид) делает все найденные ключи скомпрометированными.

| Флаг            | Значение                                          |
| --------------- | ------------------------------------------------- |
| `--prefix`      | начало адреса без `0x` (hex, регистр не важен)     |
| `--suffix`      | конец адреса                                       |
| `--count N`     | сколько кошельков найти                            |
| `--workers N`   | процессов поиска (по умолчанию — физические ядра)  |
| `--keystore-dir`| папка для файлов (по умолчанию `./keystore`)       |
| `--show-privkey`| показать приватный ключ (по умолчанию выключено)   |

Файлы: `keystore/UTC--<время>--<адрес>.json`, права `0600`.

## vanity_seed.py — BIP-39 seed-фраза

Каждая попытка — новый мнемоник (английский wordlist, энтропия `os.urandom`).
Адрес выводится на индексе `0` стандартного пути `m/44'/60'/0'/0/0`:
найденная фраза импортируется в MetaMask / Ledger / Trezor / Trust как есть.

```bash
.venv/bin/python vanity_seed.py --prefix ab            # 24 слова (256 бит)
.venv/bin/python vanity_seed.py --prefix ab --words 12 # 12 слов (128 бит)
.venv/bin/python vanity_seed.py --prefix ab --save-keystore      # + цифровой бэкап
.venv/bin/python vanity_seed.py --prefix ab --bip39-passphrase   # «25-е слово»
.venv/bin/python vanity_seed.py --prefix ab --workers 1          # однопроцессорно
.venv/bin/python vanity_seed.py --scan-indexes --workers 14 --prefix ab  # быстро
```

Seed-фраза печатается **один раз** — перепиши на бумагу. `--save-keystore`
дополнительно сохраняет выведенный из фразы ключ в зашифрованный V3 keystore.

### `--scan-indexes` — ускорение в десятки раз, ценой нестандартного индекса

Обычный режим: каждая попытка — новая фраза (PBKDF2 на каждой). В scan-режиме
**одна** случайная фраза даёт до `--max-index N` адресов (`m/44'/60'/0'/0/i`,
по умолчанию N=10000): PBKDF2 платится один раз, каждый индекс — дешёвый шаг
BIP-32. Найденная пара (фраза, индекс) сверяется с официальной деривацией
eth-account по полному пути.

**Цена**: найденный адрес обычно живёт на индексе в сотни/тысячи, а не на 0.
MetaMask покажет его только после ручного добавления такого числа аккаунтов;
нужен кошелёк с кастомным путём (Rabby, MEW) или импорт выведенного ключа
(`--save-keystore`). Для «фраза везде работает как есть» используй обычный режим.

## Скорость (замер на этой машине: 8 ядер, coincurve + пул 14 процессов)

| Символов | Среднее попыток | ключ `--walk` (~680k/с) | ключ рандом (~98k/с) | seed `--scan-indexes` (~113k/с) | seed фразы (~1.7k/с) |
| -------- | --------------- | ----------------------- | -------------------- | ------------------------------ | -------------------- |
| 4        | 65 536          | мгновенно               | ~0.7 c               | ~0.6 c                         | ~40 c                |
| 5        | 1 048 576       | ~1.5 c                  | ~11 c                | ~9 c                           | ~10 мин              |
| 6        | 16 777 216      | ~25 c                   | ~2.9 мин             | ~2.5 мин                       | ~2.7 ч               |
| 7        | 268 435 456     | ~6.6 мин                | ~46 мин              | ~40 мин                        | ~1.8 сут             |
| 8        | 4 294 967 296   | **~1.8 ч**              | ~12 ч                | **~10.6 ч**                    | ~29 сут              |

Самый быстрый режим вообще — `--walk` (приватные ключи): случайный старт +
дешёвые шаги `P += G`. Для seed-фраз лучший режим — `--scan-indexes`: PBKDF2
один раз на фразу, до `--max-index` адресов с неё (~×66 к режиму «фраза на
каждую попытку»), но найденный индекс нестандартен (см. выше). Каждый следующий
hex-символ умножает время на 16.

## Безопасность

- Запускать на чистой/**офлайн**-машине; результат забирать флешкой.
- Ключ/фраза какое-то время находятся в RAM процесса (Python не обнуляет память).
- Пароли спрашиваются через `getpass`, не через аргументы командной строки.
- Каждый keystore перед записью расшифровывается обратно и сверяется с адресом.
- BIP-39 passphrase поддерживается не всеми кошельками одинаково — потому
  опциональна (без неё фраза восстанавливается где угодно).
- 12 и 24 слова — универсальные длины; 15/18/21 валидны по BIP-39, но часть
  UI их не принимает.
